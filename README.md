# 데이터 보관소

과제 파일과 사진을 정리할 공간이 필요한 학생과 개인 사용자를 위한 서비스입니다. 저장 용량을 선택하고 파일을 추가·삭제하면서 보관함의 사용량을 확인할 수 있습니다.

- GitHub 저장소: https://github.com/koodonghyeon/uiuxprogramming
- 배포 웹페이지: https://koodonghyeon.github.io/uiuxprogramming/

## 12주차 UI 컴포넌트

- **탭**: 파일 보관·용량 선택·이용 안내를 나누어 보여줍니다. 클릭이나 좌우 방향키로 전환하면 선택 표시와 내용이 함께 바뀝니다.
- **FAQ 아코디언**: 용량 선택, 새로고침, 파일 추가 오류에 관한 질문을 넣었습니다. 질문을 클릭하거나 Enter·Space를 누르면 답변이 열리고 닫히며, ‘펼치기·접기’ 문구도 바뀝니다. 여러 답변을 함께 열어둘 수 있습니다.

디자인은 공통 CSS 클래스로, 동작은 `initTabs()`와 `initAccordion()`으로 정리했습니다. 같은 구조를 다른 곳에 추가해도 각 묶음이 독립적으로 동작합니다. Tab으로 이동할 때 초점 테두리를 표시하고, 닫힌 답변 안의 링크는 건너뜁니다.

1100px·768px·390px에서 클릭과 키보드 조작, 여러 묶음의 독립 동작을 확인했습니다. 기존 신청·파일 관리·메뉴 이동도 정상 동작합니다. 이번 수정은 로컬에만 적용했습니다.

## 11주차 접근성 개선

- 신청 버튼에 마우스를 올리면 글자 대비가 낮아짐 → 배경을 진하게 바꿔 흰 글자의 대비를 4.30:1에서 6.70:1로 높였습니다. 이메일 입력 예시도 더 밝게 조정했습니다.
- 일부 요소의 초점 테두리가 흐리거나 표시가 일정하지 않음 → 밝은 배경에는 진한 테두리, 어두운 배경에는 노란 테두리를 적용했습니다. 키보드로 이동한 항목이 상단 메뉴에 가리지 않도록 했습니다.
- 본문을 보려면 메뉴를 차례로 지나가야 함 → 첫 Tab에서 나타나는 ‘본문 바로가기’를 추가했습니다.
- 안내 탭의 선택 상태를 주로 배경색으로 구분함 → 밑줄과 ‘선택한 안내’ 문구를 함께 표시합니다. 저장 공간이 부족해질 때도 색상과 함께 정리 안내를 보여줍니다.
- 소개 제목과 하위 항목의 제목 단계가 섞여 있음 → 소개는 큰 제목, 카드 항목은 하위 제목으로 정리했습니다. 초기화 버튼도 ‘보관함 모두 비우기’로 구체화했습니다.

기존 이미지의 대체 텍스트, 입력 라벨, 파일명을 포함한 삭제 버튼 설명은 유지했습니다. 색 대비는 [W3C 색 대비 안내](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)를 참고해 계산했습니다.

Edge의 1100px·768px·390px 화면에서 Tab, Shift+Tab, Enter, Space, 방향키로 메뉴 → 신청과 오류 수정 → 파일 추가 → 필터 → 삭제·초기화를 확인했습니다. 초점 표시와 가로 잘림도 확인했고, 기존 저장 실패 후 재시도와 뒤로 가기도 정상 동작했습니다.

2026년 11월 14일에 저장소와 배포 주소가 모두 열리는 것을 확인했습니다. 11주차 수정은 로컬에만 적용했으며, 직접 업로드한 뒤 배포 화면을 다시 확인해야 합니다.

## 10주차 메뉴와 목록 탐색

10주차에는 메뉴 이동과 보관함 목록 탐색을 개선했습니다. 현재 메뉴는 배경과 밑줄로 표시하고 `aria-current`를 적용했습니다. 메뉴 이동뿐 아니라 스크롤, 새로고침, 뒤로 가기에도 현재 위치가 맞게 표시됩니다. 모바일에서는 ‘메뉴 열기·닫기’로 펼치고 접을 수 있으며, 목적지를 선택하면 메뉴가 닫힙니다.

| 메뉴 | 목적지 |
| --- | --- |
| 서비스 소개 | 서비스 설명 (`#about`) |
| 용량·기능 안내 | 보관 기능과 용량 안내 탭 (`#features`) |
| 소식 신청 | 용량과 이메일을 입력하는 신청 과정 (`#subscribe`) |
| 파일 보관함 | 파일 추가·삭제와 종류별 목록 (`#vault`) |

보관함은 신청 완료 후 사용할 수 있습니다. 먼저 메뉴로 들어가면 신청으로 이어지는 안내를 보여줍니다. 새로고침하면 신청 단계와 체험 목록은 초기화됩니다.

목록 필터는 전체·문서·사진·동영상·기타입니다. 파일 확장자를 기준으로 분류하며, ZIP과 분류되지 않은 형식은 기타에 포함합니다. 선택한 필터의 표시와 `aria-pressed`, 목록, 표시 개수가 함께 바뀝니다. 보관함이 비었을 때는 파일 추가를 안내하고, 해당 종류만 없을 때는 ‘전체 파일 보기’를 제공합니다. 필터를 바꿔도 실제 보관한 파일과 사용량은 유지됩니다.

## 앞서 추가한 입력 폼

소식 신청 폼에 ‘추가 요청 남기기’를 넣었습니다. 선택하면 요청 입력란이 나타나고, 선택을 해제하면 숨겨지면서 비활성화됩니다. 다시 선택하면 작성하던 내용은 남아 있지만, 선택을 해제한 채 제출하면 요청 내용은 저장하지 않습니다.

용량과 이메일은 필수입니다. 추가 요청을 선택한 경우에는 앞뒤 공백을 제외하고 10~200자를 작성해야 합니다. 입력 중 글자 수와 조건 충족 여부가 표시되고, 잘못 입력한 부분을 고치면 오류 안내가 사라집니다.

최종 신청도 폼의 `submit` 이벤트로 처리합니다. 저장 중에는 진행 안내를 보여주고 버튼을 잠그며, 성공하면 이메일과 요청 내용을 완료 화면에 표시합니다. 브라우저 저장이 실패하면 입력값을 유지하고 ‘다시 신청하기’로 재시도할 수 있습니다.

## 사용 방법

1. 메뉴에서 ‘소식 신청’으로 이동하고 ‘소식 신청 시작하기’를 눌러 관심 용량과 이메일을 입력합니다.
2. 확인 화면에서 내용을 확인하고 ‘소식 신청하기’를 누릅니다. 잘못 입력한 내용은 이전 단계로 돌아가 수정할 수 있습니다.
3. 신청 완료 화면에서 ‘파일 보관함 체험하기’를 누릅니다.
4. 파일을 선택한 뒤 ‘보관함에 추가’를 누르면 파일명, 크기, 사용량이 표시됩니다.
5. 문서·사진 등 필터를 눌러 목록과 표시 개수를 확인합니다. 해당 종류가 없으면 ‘전체 파일 보기’로 돌아갑니다.
6. 필요 없는 파일을 삭제하면 남은 용량이 늘어납니다. 메뉴 이동 후 뒤로 가기와 새로고침으로 현재 위치 표시도 확인할 수 있습니다.

용량은 10GB, 100GB, 1TB 중에서 고를 수 있습니다. 파일 없이도 확인할 수 있도록 1MB 문서, 2MB 사진, 6GB 동영상, 5GB 사진 모음(ZIP) 예시를 넣었습니다. 예시는 실제 파일 대신 정해진 크기로 용량을 계산합니다.

## 동작과 예외 처리

파일 선택에는 `change`, 추가에는 `submit`, 삭제와 취소에는 `click` 이벤트를 연결했습니다. 추가하기 전에 파일이 선택됐는지, 빈 파일이나 중복 파일은 없는지, 남은 용량 안에 들어가는지 확인합니다.

| 상황 | 화면 반응과 다음 행동 |
| --- | --- |
| 정상 파일 추가 | 파일 목록과 개수, 사용량을 갱신합니다. 이어서 다른 파일을 추가하거나 삭제할 수 있습니다. |
| 파일을 선택하지 않음 | 먼저 파일을 선택하라는 안내를 보여줍니다. 예시 파일로 시작할 수도 있습니다. |
| 내용이 없는 0 B 파일 | 추가하지 않고 내용이 있는 파일을 다시 선택하도록 안내합니다. |
| 중복 파일 | 중복 안내를 보여줍니다. 다른 파일을 선택하거나 기존 항목을 삭제한 뒤 다시 추가할 수 있습니다. |
| 용량 초과 | 필요한 용량과 남은 용량을 표시합니다. 기존 파일을 삭제하거나 더 작은 파일을 선택해야 합니다. |
| 파일 삭제 | 목록에서 해당 항목을 없애고 용량을 다시 계산합니다. 마지막 파일을 지우면 빈 보관함 안내를 보여줍니다. |
| 선택 취소 | 아직 추가하지 않은 선택만 취소합니다. 이미 보관한 파일은 남습니다. |
| 체험 초기화 | 모두 비울지 먼저 확인합니다. 확인하면 목록과 사용량을 초기화하고, 취소하면 그대로 유지합니다. |

중복 여부는 파일 이름, 크기, 마지막 수정 시각으로 판단합니다. 여러 파일을 한꺼번에 선택했을 때 하나라도 조건에 맞지 않으면 이번 선택은 모두 추가하지 않고 기존 목록을 유지합니다.

신청 완료 화면으로 돌아갔다가 보관함을 다시 열어도 파일 목록과 선택 중인 파일은 남아 있습니다. ‘체험 초기화’는 보관함만 비우고, 신청 화면의 ‘다시 시작하기’는 이메일과 용량을 포함한 전체 과정을 초기화합니다.

## 확인한 내용

로컬 페이지를 Edge와 Playwright로 다시 확인했습니다. 화면 너비는 1100px, 768px, 390px이며, 390px은 실제 휴대전화 대신 브라우저의 터치 에뮬레이션으로 테스트했습니다.

10주차 변경 후 메뉴 이동 → 소식 신청 → 파일 추가 → 목록 확인 → 필터 선택 순서로 조작했습니다. 세 너비에서 가로 잘림 없이 동작했으며, 기존 입력 오류 수정·조건부 입력·저장 실패 후 재시도도 확인했습니다. 이번 변경은 로컬에서 확인한 상태이며 배포는 아직 반영하지 않았습니다.

| 테스트 | 결과 |
| --- | --- |
| 메뉴 이동, 새로고침, 뒤로·앞으로 가기 | 실제 위치와 현재 메뉴 표시가 일치함 |
| 모바일 메뉴 열기·닫기, 목적지 선택 | 표시 상태와 문구, `aria-expanded`가 함께 바뀌고 선택 후 닫힘 |
| 파일 종류 필터와 결과 개수 | 선택 표시·`aria-pressed`·목록·개수가 일치하고 사용량은 유지됨 |
| 전체 목록 없음, 필터 결과 없음 | 각각 파일 추가 안내와 전체 파일 보기 안내가 표시됨 |
| 신청 후 보관함 열기 | 신청한 용량과 이메일이 표시됨 |
| 파일 2개 추가 | 파일 목록에 두 개가 표시되고 크기의 합계가 사용량에 반영됨 |
| 미선택, 빈 파일, 중복 파일 추가 | 안내가 표시되고 기존 목록과 사용량은 바뀌지 않음 |
| 10GB 보관함에 6GB 추가 후 5GB 추가 | 남은 공간이 4GB라서 두 번째 파일은 추가되지 않음 |
| 6GB 파일 삭제 후 대기 중인 5GB 추가 | 공간이 확보되고 5GB 파일 추가에 성공함 |
| 한도에 맞는 파일과 1 B 초과 파일 | 한도에 정확히 맞으면 추가되고, 초과하면 차단됨 |
| 마지막 파일 삭제 | 사용량이 0으로 바뀌고 빈 보관함 안내가 표시됨 |
| 선택 취소, 초기화 취소 | 취소 대상 외의 파일과 선택값은 유지됨 |
| 보관함 초기화, 신청 다시 시작 | 각각 정해진 범위의 입력값과 목록, 오류 상태가 초기화됨 |
| 완료 화면으로 돌아갔다가 재진입 | 보관 목록과 선택 중인 파일이 유지됨 |
| 100GB와 1TB에서 예시 두 개 추가 | 합계 11GB로 계산되고 선택한 전체 용량이 적용됨 |
| 긴 파일명과 이메일 표시 | 줄바꿈되어 표시되며 입력창과 버튼이 화면 밖으로 밀리지 않음 |
