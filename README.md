## 사용자와 서비스 목적

| 항목 | 정의 |
| --- | --- |
| 주요 사용자 | 과제·문서·사진을 정리할 저장 공간이 필요한 학생과 개인 사용자 |
| 서비스 목적 | 파일 보관 기능과 용량별 용도를 이해하고 출시 소식을 신청하도록 돕기 |
| 사용자 목표 | 자신에게 맞는 용량을 고르고 정확한 이메일 주소로 소식 신청을 완료하기 |
| 핵심 행동 | 관심 용량과 이메일 입력 → 신청 내용 확인 → ‘소식 신청하기’ 클릭 |
| 완료 조건 | 유효한 저장 용량과 이메일이 있고, 확인 단계에서 최종 신청을 눌러 ‘신청 완료’ 화면에 용량·이메일이 표시됨 |
| 받을 소식 | 정식 출시 일정, 새로운 파일 관리 기능, 저장 용량 업데이트 |

## 사용자 흐름 — 총 4단계

**시작 → 정보 입력 → 확인 → 완료**

| 단계 | 화면과 행동 | 다음 단계로 이동하는 조건 |
| --- | --- | --- |
| 1. 시작 | 필요한 정보와 절차 안내, ‘소식 신청 시작하기’ 버튼 | 시작 버튼 클릭 |
| 2. 정보 입력 | 관심 용량(10GB / 100GB / 1TB) 선택, 이메일 입력 | 두 필수 항목이 모두 유효한 상태에서 ‘입력 내용 확인하기’ 클릭 또는 Enter |
| 3. 확인 | 현재 선택한 용량·입력한 이메일·받을 소식 표시 | 내용을 확인하고 ‘소식 신청하기’ 클릭 |
| 4. 완료 | 체크 표시, ‘신청 완료’, 신청한 용량과 이메일 표시 | ‘다시 시작하기’로 전체 상태를 지우고 1단계로 이동 |

정보 입력 단계에서 시작 단계로, 확인 단계에서 정보 입력 단계로 돌아갈 수 있습니다. 이전 단계로 이동할 때 폼을 초기화하지 않으므로 선택·입력값을 유지합니다. 수정 후 확인 단계에 다시 진입하면 현재 값을 읽어 요약을 갱신합니다.

진행 표시에는 현재 단계와 완료한 단계가 구분되어 표시됩니다. 진행 표시는 이동 버튼이 아니므로 필수 입력을 건너뛰어 확인·완료 단계로 갈 수 없습니다.

## 인터랙션 시나리오

| 사용자 행동 | 이벤트 | 조건 | 화면 반응 | 다음 상태 |
| --- | --- | --- | --- | --- |
| 기능 탭 선택 | `click` | 파일 보관 / 용량 선택 / 이용 안내 중 하나 선택 | 선택 탭 강조, 연결된 콘텐츠만 표시 | 선택한 탭 |
| 소식 신청 시작 | `click` | 시작 단계 | 입력 화면과 2단계 진행 표시, 제목으로 포커스 이동 | 정보 입력 |
| 관심 용량 선택 | `change` | 허용된 용량 선택 | 추천 용도 안내, 선택란·문구의 성공 색상, 다음 버튼 문구·스타일 갱신 | 정보 입력 |
| 이메일 입력·수정 | `input` | 비어 있지 않고 `type="email"` 유효성 통과 여부 | 형식 안내와 입력란 색상, 다음 버튼 문구·스타일 갱신 | 정보 입력 |
| 미입력 상태에서 다음 버튼 클릭 | `submit` | 용량 미선택 또는 이메일 누락 | 이동 차단, 항목별 수정 방법, 첫 오류 항목으로 포커스 이동 | 정보 입력 유지 |
| 잘못된 이메일로 다음 버튼 클릭 | `submit` | 이메일 형식 오류 | 이동 차단, `name@example.com` 예시와 오류 색상 표시 | 정보 입력 유지 |
| 입력 내용 확인 | `submit` | 용량과 이메일이 모두 유효함 | 최신 용량·이메일 요약 표시, 3단계 강조 | 확인 |
| 이전 단계로 이동 | `click` | 정보 입력 또는 확인 단계 | 앞 단계 표시, 입력값 유지 | 시작 또는 정보 입력 |
| 이전 단계에서 수정 후 다시 확인 | `input` / `change` → `submit` | 수정한 값이 유효함 | 확인 화면의 용량·이메일을 최신 값으로 교체 | 확인 |
| 소식 신청 | `click` | 확인 단계이며 필수 값이 유효함 | 신청 완료 제목·체크 표시·이메일·용량, 중복 완료 방지 | 완료 |
| 처음부터 다시 시작 | `click` | 진행 중 또는 완료 상태 | 폼·오류·성공 스타일·확인/완료 문구·진행 표시·버튼 상태 초기화 | 시작 |
| 탭 키보드 이동 | `keydown` | 탭에 포커스가 있음 | 좌우 방향키·Home·End로 탭 선택과 포커스 이동 | 선택한 탭 |

## 입력 검사와 상태 관리

- 용량과 이메일은 모두 필수이며, 용량은 정의된 세 값 중 하나만 허용합니다.
- 이메일은 HTML 이메일 입력의 유효성 검사를 사용합니다. 실제 주소의 존재 여부를 확인하는 검사는 아닙니다.
- 미완성 입력에서 다음 버튼을 누를 수는 있지만, JavaScript가 단계 이동을 차단하고 수정 방법을 안내합니다. 버튼 비활성화만으로 이유를 숨기지 않도록 했습니다.
- `currentStep`으로 현재 단계를 관리하고, 각 이벤트에서 허용된 단계인지 확인합니다. 확인 단계에 있을 때만 완료 처리합니다.
- 입력·선택값은 폼 요소에 유지하고, `touched`로 항목별 오류 안내 시점을 관리합니다.
- 확인 화면은 진입할 때마다 최신 입력을 읽습니다. 사용자 입력은 `textContent`로 표시합니다.
- 완료 시 최종 신청 버튼을 비활성화하고 완료 상태에서 재실행을 차단합니다.
- ‘다시 시작하기’는 `form.reset()`과 상태 초기화 함수로 입력·선택·오류·요약·완료·진행 상태를 모두 초기화합니다. 오류가 난 진행 도중에도 초기화할 수 있습니다.

## 모바일과 접근성

- 1100px, 768px, 390px 화면 너비에 맞게 유동 너비와 미디어 쿼리를 적용했습니다.
- 모바일에서는 입력란, 확인 정보, 이전/다음 버튼을 세로로 배치하고 버튼 높이를 최소 48px로 확보했습니다.
- 긴 이메일 주소는 확인·완료 화면에서 줄바꿈하여 가로 넘침을 방지합니다.
- `label`, `required`, `aria-describedby`, `aria-invalid`, `aria-live`로 입력 목적과 오류 상태를 연결했습니다.
- 탭에는 `role="tab"`과 `aria-selected`, 진행 표시에는 `aria-current="step"`을 사용했습니다.
- 숨겨진 단계에는 `hidden`을 적용하고, 단계 전환 시 표시된 제목으로 포커스를 이동합니다.
